## 12.6 - the batch is one authority envelope with an identity
/wal/finalize-batch was deployable while the v16 batch schema was absent: no
BatchOperationId, no canonical batch digest, no K/byte limits, and no way to
answer a replayed batch. The envelope is now required (an unnamed batch is
refused, one-record finalization always remains open), the digest is computed
server-side from the ordered members' own canonical request digests, a
supplied digest is only ever CHECKED, and one batch id may never name a
different set of members - including a reordering.

## Q-03 / 12.4 - the startup-session lifecycle
Takeover-at-open is gone as a MECHANISM: activateSession is the only code
that fences, and it is one transaction that revalidates reservation,
attested process nonce, controller incarnation and generation first.
Authority lives under a controller-time lease over a persisted NONDECREASING
floor; finalize/setBudgets/outboxAck revalidate the lease before any
counter/outbox is consumed; expiry is terminal. Session ids are single-use.
The legacy registerSession is a macro over reserve->attest->activate, so the
three-lane pin (register-fences-predecessor) keeps its trace while the
directive's rule ("a new random session id cannot fence anyone" outside the
protocol) holds structurally. Reads survive expiry (12.4: expiry blocks new
mutations, it does not make durable history unreadable).
