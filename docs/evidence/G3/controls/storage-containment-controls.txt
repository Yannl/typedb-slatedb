## Q-14 - a failed object-cache wipe is propagated, not discarded
The FIRST version of this control was wrong and is recorded here because the
mutant caught it: it injected a non-directory at the cache path and asserted
that `open_remote` failed. It passed under the mutant, because `create_dir_all`
fails on the same obstruction whether or not the wipe's error is discarded -
so it proved nothing. The failure that actually matters is a PARTIAL wipe:
`remove_dir_all` deleting some entries and erroring midway leaves the directory
present, `create_dir_all` then succeeds, and the survivors are served for this
materialisation's object paths.

The wipe is now a named function and the control asserts its own result.
